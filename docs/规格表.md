# 规格表（唯一事实来源）

实现、参考评测器与测试都以本表为准。任何与题面冲突的地方，先改本表再改代码，并在 §9 变更记录里写一行。

记号：`t` 当前 tick；`c/m` 作业 CPU/内存需求；`p_d` 机房单价；`s` 作业启动 tick；`r` 释放 tick。

---

## 1. tick 主循环（唯一状态机）

```
读 TICK t ne nq
重复 ne 次：读一个事件（WF 额外读 n 行作业行）→ 立即按 §3 应用
按题目给定顺序回答 nq 个对账 → 组装 "ANS a1 .. anq"
逐条生成指令 → 每条按 §5 检查、若合法再按 §5 应用（立即改状态）
输出指令行 + "END" → flush
t == T 时立即 exit(0)
```

- **对账取值时刻 = 全部事件处理完、任何本轮指令执行前。**
- 对账答案与本轮指令无关；但本轮指令按输出顺序连续生效（第 k 条看到的是第 k-1 条之后的状态）。
- `nq = 0` 也必须输出一行 `ANS`。每 tick 指令数 ≤ 20000（本实现自身上限更小）。

## 2. 状态清单

| 组 | 状态 | 维护方式 |
|---|---|---|
| 时间 | `t` | 主循环 |
| 机器 | `healthy[x]`、`usedCpu[x]`、`usedMem[x]` | RUN 增、DONE/KILL/FAIL 减 |
| 机器缓存 | `mPos[x]` (层→节点)、LRU 双链表、`mUsed[x]` | §6 |
| 机架缓存 | `rPos[r]`、LRU、`rUsed[r]` | §6 |
| 网络 | `linkUp[e]`、`dcUp[d]`、`topoVer`、`distCache[ver][node]` | 拓扑事件递增 `topoVer` |
| 租户 | `parent[k]`、`quota[k]`、`used[k]`（子树运行中 CPU） | RUN 沿父链 +c，释放沿父链 −c |
| 撤销栈 | `undo[(tenant, oldQuota)]` | QUOTA 压栈，UNDO 弹栈 |
| 账单 | `settled[k]`、`rate[k]`、`inter[k]`，满足 `BILL(o,t) = settled[o] + rate[o]*t + inter[o]` | 见 §4 |
| 工作流 | `o, v, dl, arrive, jobs[]（输入拓扑序）, doneCnt, total, abandoned, finishTick` | WF/DONE/DROP |
| 作业 | `state ∈ {PENDING, RUNNING, DONE}`、`machine`、`startTick`、`remPreds`、`preds[]`、`succs[]`、`doneRack`、`c,m,e,img,srcRack,zIn,zOut` | §3 |
| 日志 | 每机器 `alarmByTick[x][t]` 环形窗口 + 窗口和 | LOG 累加 |
| 编码 | `huffCode[9]`、AC 自动机（fail/转移、重叠计数） | 初始化构建一次 |

外部 ID（工作流 9 位、作业 9 位）一律 `unordered_map<int,int>` 映射到连续下标；租户/机器/机架/层/镜像直接下标。

## 3. 事件 → 状态修改

| 事件 | 语义与状态修改 | 边界 |
|---|---|---|
| `DONE j` | 要求 `j` 为 RUNNING：按 `r=t` 结算运行费（§4.2）、释放 CPU/内存、`state=DONE`、`doneRack=rack(machine)`；`wf.doneCnt++`；`remPreds[succ]--`；若 `doneCnt==total` 则 `finishTick=t`、工作流完成 | 同 tick 多个 DONE 按输入顺序；同 tick DONE 后对账应看到释放后的状态 |
| `FAIL x` | 对 `x` 上每个 RUNNING 作业：按 `r=t` 结算运行费、释放资源、`state=PENDING`、`machine=-1`；然后清空机器缓存（`mUsed=0`、索引清空）；`healthy[x]=false`；**机架缓存与 `doneRack` 不变** | 故障不清除作业的 `doneRack`；已花的传输/拉取费不退 |
| `UP x` | `healthy[x]=true`；机器缓存保持为空（FAIL 已清） | 不给 `UP` 之前不存在的状态补缓存 |
| `DCDOWN d` / `DCUP d` | 该机房所有网络节点不可用/恢复；`topoVer++` | 只影响网络，不影响机器健康 |
| `LDOWN e` / `LUP e` | 链路断开/恢复；`topoVer++` | 边编号是输入顺序 0..E-1 |
| `QUOTA t q` | `undo.push({t, quota[t]})`；`quota[t]=q` | 允许 `q < used[t]` |
| `UNDO k` | 弹 `k` 次，每次 `quota[tenant]=oldQuota` | 栈空时题目不会给 `UNDO`；实现仍需防止越界 |
| `LOG x b h` | 由 `b`、`h` 解码出符号串（§7），算告警分 `sc`，累加到 `alarmByTick[x][t]`，维护窗口和 | 最后不足 4 位的补零位必须丢弃；`b=0` 时符号串为空、分数 0 |
| `WF w o v dl n` + n 行 | 建工作流与作业，`remPreds = k`；前驱必是同工作流已列出的作业，故输入顺序即拓扑序 | `WF` 的 n 行作业行**不是事件**，不占 `ne` |

事件的类别顺序由评测程序保证（DONE/FAIL/UP/DCDOWN/DCUP/LDOWN/LUP/QUOTA/UNDO/LOG/WF），实现按读到的顺序处理即可。

## 4. 账单与配额

### 4.1 表示

运行中作业对每个祖先租户 `a`（含自身）贡献：

```
rate[a] += c * p_d
inter[a] -= c * p_d * s
```

于是 `BILL(o,t) = settled[o] + rate[o]*t + inter[o]` 恰为「tick 1..t-1 的运行费 + 已发生的传输/拉取费」，运行中作业按 `r=t` 计。

### 4.2 结算（DONE / KILL / FAIL，均 `r=t`）

```
fee = c * p_d * (t - s)
对 o 的每个祖先 a：settled[a] += fee; rate[a] -= c*p_d; inter[a] += c*p_d*s
```

### 4.3 一次性费用（RUN 时）

```
传输费 = Σ z * dist * U_net        （对每个需传输的输入）
拉取费 = Q_reg * U_reg              （机架拉取不计费）
对 o 的每个祖先 a：settled[a] += 传输费 + 拉取费
```

已发生费用**永不退还**（KILL/FAIL/DROP 都不退）。

### 4.4 对账

| 对账 | 答案 | 读取 |
|---|---|---|
| `BILL o` | `settled[o] + rate[o]*t + inter[o]` | 账单三元组 |
| `HEAD o` | `min_{a ∈ path(root..o)} (quota[a] - used[a])` | `quota`、`used` |
| `ROUTE a b` | `dist(rack a, rack b)`，不可达 `-1` | 网络 |
| `ALARM x` | `Σ_{τ=t-W+1..t} alarmByTick[x][τ]`（τ<1 不计） | 日志窗口 |
| `SLACK j` | `CP - ES(j) - TL(j)`（§8），`j` 已完成时按 0 | 工作流 DAG |
| `CACHE x` | `mUsed[x]` | 机器缓存 |
| `RCACHE r` | `rUsed[r]` | 机架缓存 |

## 5. 指令 → 检查 + 修改

| 指令 | 合法性检查（全部满足才执行） | 执行 |
|---|---|---|
| `RUN j x` | ① `j` PENDING 且工作流未 abandoned；② `remPreds[j]==0`；③ `healthy[x]`；④ `usedCpu[x]+c ≤ cpu[x]`、`usedMem[x]+m ≤ mem[x]`；⑤ 对 `j` 租户到根的每个 `a`：`used[a]+c ≤ quota[a]`；⑥ 每份需传输输入（外部输入所在机架 `s`、每个已完成后继前驱的 `doneRack`，且 `≠ rack(x)`）都能从 `rack(x)` 到达 | §5.1 |
| `KILL j` | `j` RUNNING | 按 `r=t` 结算、释放、`state=PENDING`、`machine=-1`；**缓存不动** |
| `DROP w` | `w` 已到达、未完成、未 abandoned，且此刻工作流内**无 RUNNING 作业** | `abandoned=true`；只做标记，不结算、不释放（因已无运行作业） |

`j` 已 DONE、或工作流已完成/已 abandoned（对 `DROP` 而言）都算非法。非法指令 = 该组必然失败，本地评测器必须报出「第一次非法指令」。

### 5.1 RUN 的完整执行顺序

1. **收集输入**：`[(srcRack, z)]`
   - 外部输入：若 `srcRack != -1` 且 `srcRack != rack(x)`，加入 `(srcRack, zIn)`；
   - 每个前驱 `p`：若 `p.doneRack != rack(x)`，加入 `(p.doneRack, zOut[p])`；
   - 与 `rack(x)` 同机架的输入**不传输、不检查路由**（也不检查其节点是否停电）。
   - 每份：`T = dist(rack(x), src) + ceil(z / B_net)`，`费 = z * dist * U_net`；`dist == -1` ⇒ 非法。
   - `T_tr = max(各份 T)`，无输入时为 0。
2. **拉取镜像**：按 `img` 的层序列**从底到顶**逐层按 §6 处理，累加 `Q_reg`、`Q_rack`，同时改写两级缓存（不可回滚）。
   - `T_pull = ceil(Q_reg / B_reg) + ceil(Q_rack / B_rack)`；拉取费 `= Q_reg * U_reg`。
3. **费用记账**：`settled` 沿租户父链加 `传输费 + 拉取费`。
4. **占用**：`usedCpu[x]+=c`、`usedMem[x]+=m`；`used[a]+=c` 沿父链；`state=RUNNING`、`machine=x`、`startTick=t`。
5. **运行中费率**：`rate[a]+=c*p_d`、`inter[a]-=c*p_d*t` 沿父链。
6. **完成时刻**（仅评测器记录）：`S = max(T_tr, T_pull)`，`finish = t + S + dur`（`dur` 真实时长，我方不可见）。

> 我方实现不预测 `DONE`：完成只由 `DONE` 事件确认。`RUN` 后的所有状态在事件到达前保持不变。

## 6. 两级镜像缓存（每次 `RUN` 逐层调用）

```
处理层 l：
  if l ∈ mPos[x]:            移机器 LRU 到最近使用端
  elif l ∈ rPos[r]:          Q_rack += size[l]; 移机架 LRU 到最近使用端；插入机器
  else:                      Q_reg  += size[l]; 插入机架；插入机器
插入机器：若已在则移到最近端；否则加到最近端，mUsed += size[l]，逐层从最久端淘汰直到 mUsed ≤ mcap[x]
插入机架：同上，容量 rcap[r]
```

- 淘汰按「层」为单位整体淘汰（大小累加），可淘汰刚插入的层（若单层就超容量）。
- 大于容量的层：插入后立刻被淘汰，但 `Q_reg/Q_rack` 与费用照计。
- `CACHE x = mUsed[x]`、`RCACHE r = rUsed[r]`。
- `FAIL` 清空机器缓存（`mUsed=0`），机架缓存保留；`UP` 不补。

## 7. 编码与告警

### 7.1 Huffman（初始化唯一确定）

```
heap ← 9 个 (freq[s], id=s)，按 (freq, id) 小根堆
nextId = 9
while size > 1:
    A = pop(); B = pop()       # A 为左子树，B 为右子树
    push (A.w+B.w, nextId++)
从根走：左 0、右 1，得到 9 个符号的码
```

### 7.2 日志解码

`h` 为十六进制串，前 `b` 位有效（每 4 位一个十六进制数字，高位在前，末位补 0 丢弃）。
逐位沿 Huffman 树下行，到叶子输出符号并回到根；共消耗恰好 `b` 位。

### 7.3 告警分

AC 自动机（模式串可重复、可重叠）：一行符号串的分数 = `Σ` 每次出现（含重叠、含同一模式多次出现）的权重。
若模式串重复出现（相同串给两次），视为两个模式，各自计数。
机器 `x` 在 `t` 的告警值 = tick `[t-W+1, t]` 内全部日志行分数之和。

## 8. SLACK

对工作流 `w`，取 `U = {u : u.state != DONE}`，边集 `E' = {(u,v) : u,v ∈ U, v 依赖 u}`：

```
ES(u) = max_{p→u ∈ E'} ( ES(p) + e[p] )，无前驱为 0                 # 不含 u 自身
TL(u) = e[u] + max_{u→v ∈ E'} TL(v)，无后继为 e[u]                 # 含 u 自身
CP    = max_{u ∈ U} ( ES(u) + TL(u) )
SLACK(j) = CP - ES(j) - TL(j)
```

- 运行中作业也用估计时长 `e`（不是真实时长）。
- `j` 已完成：`SLACK` 无定义；实现返回 0（题目不会问）。
- 拓扑序 = 输入顺序（前驱必在同行之前列出）。
- 缓存：按工作流 `doneCnt` 维护版本号，版本不变时复用结果。

## 9. 收益、利润与终点

```
G = max(5, floor((dl - a) / 3))
f ≤ dl            → v
dl < f < dl + G   → floor(v * (dl + G - f) / G)
f ≥ dl + G        → 0
```

- 工作流完成才结算收益；`DROP`/未完成 = 0；被 abandoned 的工作流即使之后…（不会完成）。
- 利润 = `Σ 收益 - Σ 费用`。
- 第 `T` tick 结束时仍在运行的作业，按 `r = T+1` 计费（只影响最终利润，不影响 `BILL` 对账）。

## 10. 网络

- 节点 `= d*(N/D)` 起，机房 `d` 拥有 `[d*N/D, (d+1)*N/D - 1]`。机架 `r` 接在 `node_r`。
- `dist(a,b)`：从 `node_a` 到 `node_b`，只经过「所在机房 `dcUp`」的节点与 `linkUp` 的边，边权相加。
- `a == b` 且该机房未停电 → `0`；否则若任一节点所在机房停电 → `-1`（`a==b` 也 `-1`）。
- 不可达 → `-1`。`RUN` 时 `dist == -1` 的输入使 `RUN` 非法。
- 拓扑事件只递增版本号，距离按版本惰性计算：`distCache[ver][srcNode]`（机架对应节点为源，最多 30 个源；多源可合并）。

## 11. 边界清单（每条都要有对应测试）

1. 同 tick 先 `DONE` 后对账（费用/配额已释放）。
2. 同 tick `FAIL` 早于 `DONE`：先按运行中结算，再 `DONE` 找不到运行作业（题目不会产生，实现需容错）。
3. `UP` 后 `CACHE == 0`。
4. `KILL` 后再 `RUN` 同作业（缓存仍在，命中成本更低）。
5. `DROP` 时有运行作业 ⇒ 非法。
6. 配额下调至低于 `used`（合法）；后续 `RUN` 逐级检查新配额。
7. 多次 `QUOTA/UNDO` 混合（栈语义：后进先出）。
8. 同机架输入（不传输、不查路由）、不同机架同节点（`dist=0` 仍需检查可达）。
9. 断链/停电/恢复后距离更新；`ROUTE a a` 在停电时 `-1`。
10. 镜像重复层、跨镜像共享层、机器命中（只动机器 LRU）、机架命中、仓库拉取、插入即淘汰、容量恰好相等。
11. Huffman 同频按编号裁决；`b` 非 4 的倍数时尾部补零位丢弃。
12. 模式重叠（`aa` 在 `aaa` 中两次）、模式重复。
13. 窗口首 tick（`t < W`）、末 tick。
14. 分叉/汇合 DAG；前驱完成后未完成子图变化；同工作流重复 `SLACK`。
15. `nq=0`、零指令、连续多轮、末轮退出。
16. 第 `T` 轮仍运行：`BILL` 用 `r=t`，最终利润用 `r=T+1`。
